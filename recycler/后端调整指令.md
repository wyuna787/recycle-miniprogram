| 取消申请 `cancelApply*` | 商家/回收商申请取消、平台审核 | ❌ 无接口（仅有平台 close） |
| `recycler_keeper` 角色 | 回收商库管 | ⚠️ `account_utils` 已引用，但 `models.py` 注释/部分校验未覆盖 |

> 计算口径（务必与前端 `utils/moneyMock.js` 完全一致，否则两端对不上）：
> ```
> 平台服务费率 = 0.02
> 平台服务费   = round2(回收商成交价 × 0.02)
> 平台扣费后基数(merchantBase) = round2(成交价 − 平台服务费)
> 老板抽成 = round2(基数 × 老板比例)
> 员工抽成 = round2(基数 × 员工比例)
> 真实展示金额(real) = round2(基数 − 老板抽成 − 员工抽成)
> 工作台展示金额(display) = floor(real)   # 去小数
> round2(x) = round(x*100)/100
> ```

## 3. 金额计算工具（新增 `money_utils.py`）

直接移植前端 `moneyMock.js`，保证两端一致：

```python
PLATFORM_FEE_RATE = 0.02

def round2(v):
    return round((v or 0) * 100) / 100

def floor_money(v):
    import math
    return int(math.floor(v or 0))

def build_amount_snapshot(quote_amount: float, owner_rate: float = 0, staff_rate: float = 0) -> dict:
    full = round2(quote_amount)
    platform_fee = round2(full * PLATFORM_FEE_RATE)
    base = round2(full - platform_fee)
    owner_c = round2(base * (owner_rate or 0))
    staff_c = round2(base * (staff_rate or 0))
    real = round2(base - owner_c - staff_c)
    return {
        "recycler_quote_amount": full,
        "platform_fee_rate": PLATFORM_FEE_RATE,
        "platform_fee_amount": platform_fee,
        "merchant_base_amount": base,
        "merchant_owner_rate": owner_rate or 0,
        "merchant_owner_commission": owner_c,
        "merchant_staff_rate": staff_rate or 0,
        "merchant_staff_commission": staff_c,
        "merchant_real_amount": real,
        "merchant_display_amount": floor_money(real),
    }
```

## 4. 资金池状态机（新增 `fund_utils.py`）

移植前端 `utils/fundFlow.js`。**所有写操作放进同一个 DB 事务，并保证幂等**（冻结只在确认成交一次、释放只在仍冻结时一次）。

```python
from datetime import datetime
from models import RecyclerFundPool, FundFlow
from money_utils import round2, PLATFORM_FEE_RATE

def _get_or_create_pool(db, company_id):
    pool = db.query(RecyclerFundPool).filter(RecyclerFundPool.company_id == company_id).first()
    if not pool:
        pool = RecyclerFundPool(company_id=company_id, balance=0, frozen_amount=0, deducted_amount=0)
        db.add(pool); db.flush()
    return pool

def get_available(db, company_id):
    pool = _get_or_create_pool(db, company_id)
    return round2((pool.balance or 0) - (pool.frozen_amount or 0))

def _add_flow(db, type, company_id, amount, **ctx):
    db.add(FundFlow(type=type, company_id=company_id, amount=round2(amount),
                    order_no=ctx.get("order_no"), order_id=ctx.get("order_id"),
                    merchant_id=ctx.get("merchant_id"), operator=ctx.get("operator"),
                    remark=ctx.get("remark"), create_time=datetime.now()))

def freeze_fund(db, company_id, amount, **ctx):
    amount = round2(amount)
    if amount <= 0:
        return {"ok": False, "msg": "冻结金额不正确"}
    if amount > get_available(db, company_id):
        return {"ok": False, "msg": "可用余额不足"}
    pool = _get_or_create_pool(db, company_id)
    pool.frozen_amount = round2((pool.frozen_amount or 0) + amount)
    _add_flow(db, "freeze", company_id, amount, remark="商家确认成交,冻结额度", **ctx)
    return {"ok": True}

def release_fund(db, company_id, amount, **ctx):
    amount = round2(amount)
    if amount <= 0:
        return {"ok": False}
    pool = _get_or_create_pool(db, company_id)
    pool.frozen_amount = round2(max(0, (pool.frozen_amount or 0) - amount))
    _add_flow(db, "release", company_id, amount, remark="订单取消/关闭,释放冻结", **ctx)
    return {"ok": True}

def deduct_fund(db, company_id, amount, **ctx):
    amount = round2(amount)
    if amount <= 0:
        return {"ok": False}
    pool = _get_or_create_pool(db, company_id)
    pool.frozen_amount = round2(max(0, (pool.frozen_amount or 0) - amount))
    pool.balance = round2(max(0, (pool.balance or 0) - amount))
    pool.deducted_amount = round2((pool.deducted_amount or 0) + amount)
    _add_flow(db, "deduct", company_id, amount, remark="商家已发货,冻结转扣款", **ctx)
    platform_fee = round2(amount * PLATFORM_FEE_RATE)
    if platform_fee > 0:
        _add_flow(db, "platform_fee", company_id, platform_fee, remark="平台 2% 服务费", **ctx)
    return {"ok": True, "platform_fee": platform_fee}

def record_recharge_flow(db, company_id, amount, **ctx):
    # 余额在审核接口里加，这里只补一条流水
    _add_flow(db, "recharge", company_id, round2(amount), remark="充值审核通过,额度入账", **ctx)

def release_if_frozen(db, order, **ctx):
    # 幂等：仅当订单仍冻结(未扣款)才释放
    if not order or order.fund_status != "frozen":
        return {"released": False}
    amount = order.fund_frozen_amount or order.recycler_quote_amount or order.accepted_price or 0
    r = release_fund(db, order.recycler_company_id, amount, order_no=order.order_no, order_id=order.id, **ctx)
    if r.get("ok"):
        order.fund_status = "released"
    return {"released": bool(r.get("ok")), "amount": round2(amount)}
```

## 5. 订单生命周期接入资金（改 `main.py` 现有接口）

把状态机挂到已有的订单流转上（对应前端 P1/P7）：

1. **确认成交**（`/api/quotes/{quote_id}/accept`，第 718 行）：创建 `Order` 后，
   - 读商家老板/员工的抽成比例（`CommissionRate`，按 `inquiry.merchant_id` 找员工 + 其公司老板）。
   - `snap = build_amount_snapshot(quote.price, owner_rate, staff_rate)`，把 `snap` 各字段写入 `order`。
   - `freeze_fund(db, order.recycler_company_id, order.accepted_price, order_no=order.order_no, order_id=order.id, merchant_id=order.merchant_id, operator=当前用户)`；成功则 `order.fund_status="frozen"; order.fund_frozen_amount=order.accepted_price`。
   - 可用余额不足时：返回 400，**不创建订单 / 回滚**（与前端"冻结失败"提示一致）。
   - 同一事务 `db.commit()`。

2. **发货**（`/api/orders/{order_id}/ship`，第 833 行）：状态转 `shipped` 后，
   - `if order.fund_status == "frozen": r = deduct_fund(...); order.fund_status="deducted"; order.fund_deducted_amount=order.fund_frozen_amount`（幂等，避免重复扣）。

3. **平台关闭**（`/api/admin/orders/{order_id}/close`，第 1066 行）：置 `closed` 后 `release_if_frozen(db, order, operator="平台管理员")`。

4. **取消申请 + 审核**（后端缺，需新增，见第 6 节）：审核通过置 `cancelled/closed` 后 `release_if_frozen(...)`。

> 说明：已扣款（`deducted`）订单关闭/取消时 `release_if_frozen` 自动 no-op，不会错误退款，符合前端口径。

## 6. 新增接口清单（`main.py` + `schemas.py`）

下表的接口对应前端各页对 localStorage 的读写，**路径尽量沿用 `/api/...` 风格**，前端只需把对应 `uni.getStorageSync/setStorageSync` 换成 `api/*.js` 调用。

### 6.1 资金池
- `GET /api/fund/pool/{company_id}` → `{company_id, company_name, balance, frozen_amount, deducted_amount, available_amount}`。权限：本公司回收商三角色 + 平台。
- `GET /api/admin/fund/pools` → 全部资金池列表。权限：平台。（前端"平台资金池管理"页用）
- `POST /api/admin/fund/pools/{company_id}/set` body `{balance}` → 平台直接设置余额（前端 `platform/fund` 页）。权限：平台。建议同时写一条备注流水。

### 6.2 抽成比例
- `GET /api/commission/rate?user_id=` → `{user_id, rate}`。
- `POST /api/commission/rate` body `{user_id, rate}` → 设置自己的比例（员工只能设自己，老板可设自己；老板查看员工用下条）。权限：本人 / 商家老板。
- `GET /api/commission/rates?company_id=` → 商家公司全员比例（老板视角）。权限：商家老板 / 平台。
  对应前端 `merchantCommissionRateMap` + `pages/merchant/commission`。

### 6.3 充值
- `POST /api/recharge/apply` body `{company_id, amount, proof_image}` → 创建 pending 申请。权限：`can_recharge`（回收商老板/库管）。
- `GET /api/recharge/applies?company_id=&status=` → 申请列表（回收商看本公司，平台看全部）。
- `POST /api/admin/recharge/{apply_id}/approve` → 审核通过：`pool.balance += apply.amount` 且 `record_recharge_flow(...)`，置 approved。权限：平台。
- `POST /api/admin/recharge/{apply_id}/reject` body `{reason}` → 置 rejected。权限：平台。

### 6.4 资金流水
- `GET /api/fund/flows?company_id=` → 某公司流水（回收商本公司）。
- `GET /api/admin/fund/flows?type=&company_id=` → 平台全量流水，支持按类型筛选。权限：平台。
  对应前端 `pages/recycler/settlement`、`pages/platform/finance`、`pages/platform/dashboard`。

### 6.5 取消申请（后端当前缺）
- `POST /api/orders/{order_id}/cancel-apply` body `{reason}` → 商家/回收商发起取消申请，置 `cancel_apply_status="pending"`（给 `orders` 再补 `cancel_apply_*` 字段或单开一张表）。
- `POST /api/admin/orders/{order_id}/cancel-approve` → 通过：订单 `cancelled`、`release_if_frozen(...)`。权限：平台。
- `POST /api/admin/orders/{order_id}/cancel-reject` body `{reason}` → 驳回。权限：平台。
  对应前端 `merchant/order`、`recycler/order` 的 `cancelApply*` 与 `platform/payment` 的 `approveCancel`。

### 6.6 数据分析（二选一）
前端 `pages/merchant/analysis`、`pages/recycler/analysis`、`pages/platform/dashboard` 目前在前端聚合。两种落地方式：
- **方式 A（推荐，省事）**：后端把订单 `selected*` 快照、流水、资金池如实返回，前端继续用现有聚合逻辑，无需新接口。
- **方式 B**：后端出聚合接口，如 `GET /api/analysis/merchant?scope=`、`GET /api/analysis/recycler?scope=`、`GET /api/analysis/platform`，按角色 `scope`（all/company/self）过滤后返回统计。指标见前端分析页：真实成交价、平台抽成、老板/员工抽成、展示金额、成交数、员工业绩、报价成功率、资金池、扣款/充值流水。

对应 `schemas.py` 追加各请求体（`SetFundBalanceRequest{balance}`、`SetCommissionRequest{user_id,rate}`、`RechargeApplyRequest{company_id,amount,proof_image}`、`RejectRequest{reason}`、`CancelApplyRequest{reason}` 等）。

## 7. 权限对齐（与前端 `utils/permission.js` 一致）

## 8. 数据库迁移（SQLite）

`recycle.db` 是 SQLite，SQLAlchemy 默认 `create_all` 只建新表、**不会给旧表加列**。两种做法：

- **开发期最简（数据可丢）**：删 `recycle.db` → 重启服务由 `Base.metadata.create_all` 重建全部表 → 跑 `/dev/init` 重新灌种子数据。
- **保留数据**：手动给 `orders` 加列并建新表，例如：
  ```sql
  ALTER TABLE orders ADD COLUMN recycler_quote_amount FLOAT;
  ALTER TABLE orders ADD COLUMN platform_fee_rate FLOAT DEFAULT 0.02;
  ALTER TABLE orders ADD COLUMN platform_fee_amount FLOAT;
  ALTER TABLE orders ADD COLUMN merchant_base_amount FLOAT;
  ALTER TABLE orders ADD COLUMN merchant_owner_rate FLOAT DEFAULT 0;
  ALTER TABLE orders ADD COLUMN merchant_owner_commission FLOAT;
  ALTER TABLE orders ADD COLUMN merchant_staff_rate FLOAT DEFAULT 0;
  ALTER TABLE orders ADD COLUMN merchant_staff_commission FLOAT;
  ALTER TABLE orders ADD COLUMN merchant_real_amount FLOAT;
  ALTER TABLE orders ADD COLUMN merchant_display_amount INTEGER;
  ALTER TABLE orders ADD COLUMN fund_status VARCHAR;
  ALTER TABLE orders ADD COLUMN fund_frozen_amount FLOAT;
  ALTER TABLE orders ADD COLUMN fund_deducted_amount FLOAT;
  -- 新表由 create_all 自动建：recycler_fund_pools / fund_flows / recharge_applies / commission_rates
  ```
  长期建议引入 Alembic 做版本化迁移。
- 别忘了在 `database.py`/启动处 `import` 新模型类，否则 `create_all` 不会建表。
- `/dev/init` 种子里给每个回收商建一条 `RecyclerFundPool`（初始余额可给个测试值），方便联调。

## 9. 前端对接改造（`order dishes/二手商城交易平台/`）

后端接口就绪后，前端把 localStorage 换成接口调用：

1. `utils/request.js` 的 `BASE_URL` 指向后端地址。
2. 在 `api/` 下新增 `fund.js`（资金池/流水/充值）、`commission.js`（抽成），按第 6 节路径封装；订单生命周期沿用 `api/trade.js`。
3. 逐页替换（storage key → 接口）：
   - `utils/fundFlow.js`：`loadFunds/getFund/freezeFund/...` 改为调接口（或保留同名签名、内部换成 `await api`）。
   - `pages/recycler/settlement`、`pages/platform/fund`、`pages/platform/finance`、`pages/platform/dashboard` → 资金/流水接口。
   - `pages/merchant/commission` → 抽成接口。
   - `pages/recycler/analysis`、`pages/merchant/analysis` → 方式 A 直接用订单/流水接口数据，或方式 B 调聚合接口。
   - `pages/platform/payment` 的充值审核、取消审核 → 对应 6.3 / 6.5 接口。
4. `utils/permission.js` 保持作为前端体验层；真正的权限以后端校验为准。
5. 金额：前端展示用 `merchant_display_amount`，结算/分析用 `merchant_real_amount`，与后端快照字段一一对应。

## 10. 验收清单（端到端）

- [ ] 商家确认成交 → 回收商资金池"冻结↑、可用↓"，生成 freeze 流水；可用不足时确认失败且不建单。
- [ ] 商家发货 → "冻结→已扣款"，余额↓，生成 deduct + platform_fee 两条流水。
- [ ] 平台关闭 / 取消审核通过（仍冻结时）→ 释放冻结，可用恢复，生成 release 流水；已扣款单关闭不退款（no-op）。
- [ ] 充值申请 → 平台通过 → 余额↑且有 recharge 流水（数据总览充值统计有数）。
- [ ] 抽成：员工设自己比例、老板看全员；成交金额按"平台 2% → 老板 → 员工"算出 real/display，与前端一致。
- [ ] 真实金额留小数、展示金额去小数；订单快照不随后续比例变更而变。
- [ ] 权限：员工只看自己数据、不能充值/确认成交/改他人报价；平台看全量；越权接口返回 403。
- [ ] 数据分析三端数字与流水/订单可对账。

## 11. 注意事项

- **金额精度**：统一 `round2`，避免浮点误差累积；展示再 `floor`。生产建议金额用整数分或 Decimal。
- **并发与幂等**：冻结/扣款/释放放进事务；用订单 `fund_status` 做幂等门闩（已 frozen 才扣、已 frozen 才释放），防重复提交。
- **快照而非实时算**：订单成交时把抽成快照写死到 `orders`，历史订单不受日后比例调整影响。
- **安全**：所有权限以后端为准，前端 `permission.js` 仅控制入口/按钮的展示。
- **流水只增不改**：`fund_flows` 作为账本，任何资金动作都补一条，便于对账与排查。
